Executive assessment

The current version is substantially better than the original monolithic release: CSS syntax defects were corrected, JSON emission was hardened, several values are escaped, collectors were split into two JavaScript files, and stable/session hashes were separated. The application is useful as an intranet diagnostics demonstrator, but it should not yet be treated as a scientifically calibrated device-identity system or exposed to untrusted users.

The most serious remaining correctness bug was an orchestration race. Multiple collectors were started without awaiting their promises, while the master hash and report were finalized immediately afterward. The PR accompanying this report adds an audited orchestrator that waits for all collectors before hashing and exporting.

High-priority findings

HIGH Collector completion race

main() called many runStep() promises without await. WebRTC, fonts, storage, feature, math, performance, and PHP rendering could still be running when computeMasterHash() executed. Results could vary with machine speed and event timing.

Status: fixed in this PR by replacing the orchestrator with fully awaited parallel groups.

HIGH Excessive server and request disclosure

The PHP layer serializes all scalar $_SERVER values and all request headers into client-visible JavaScript and the exported report. Depending on server configuration this can expose internal paths, hostnames, proxy topology, authentication headers, cookies, virtual-host details, and software versions.

Recommendation: use an explicit allowlist; exclude HTTP_AUTHORIZATION, cookies, proxy authorization, filesystem paths, and server internals by default. Add an opt-in “diagnostic/full server dump” mode.

HIGH Incomplete DOM-injection boundary

The rendering abstraction still uses innerHTML for every value. An esc() helper exists, but safety depends on every caller remembering to use it. Several browser-provided strings and exception messages are not consistently escaped. This is fragile and makes future regressions likely.

Recommendation: render text with textContent; represent tags and line breaks as DOM nodes or explicit trusted-value objects. Treat all browser, header, device, voice, codec, permission, and exception strings as untrusted.

Portability review

Safari / iOS / iPadOS

  • Secure-context and permission-gated APIs vary sharply.
  • AudioContext behavior may require user activation in some contexts.
  • iOS third-party browser identification requires dedicated tokens.
  • navigator.standalone is useful but narrow.

Firefox

  • Resist Fingerprinting clamps or spoofs many values.
  • Permissions names and support differ.
  • Battery and network APIs are absent.
  • Canvas extraction may prompt or be randomized.

Chromium / Edge

  • High-entropy UA-CH can be policy- or permission-limited.
  • Accept-CH behavior depends on HTTPS and navigation lifecycle.
  • Private Network Access and future privacy-budget changes may reduce signals.

Performance review

  • Parallel collection is appropriate, but expensive probes should be grouped by cost and optionally disabled.
  • Font enumeration and large DOM row insertion should use DocumentFragment to reduce repeated layout work.
  • Repeated innerHTML += reparses existing status-bar markup; append DOM nodes instead.
  • Canvas/WebGL/audio probes should record duration and enforce per-probe deadlines.
  • Speech synthesis voice loading is event-driven and browser-dependent; retain a bounded timeout and mark incomplete results explicitly.
  • Exported raw data can be large; add compact and redacted export modes.

Recommended feature roadmap

  1. Milestone 1 — Trustworthy execution: complete await/timeout handling, sanitize all DOM output, server-data allowlist, CSP-compatible event handling, automated syntax/static tests.
  2. Milestone 2 — Explainable fingerprints: canonical signal schema, per-signal stability/availability/confidence, SHA-256 identifiers, diff two scans, redacted export.
  3. Milestone 3 — Cross-browser validation: Playwright matrix for Chromium/Firefox/WebKit, mobile-device emulation, secure/insecure context tests, privacy-mode fixtures.
  4. Milestone 4 — Empirical value: optional local-only history, repeatability statistics, confidence calibration, documented false-positive/false-negative limits.

Validation limits

This was a source-level review of the current repository and its commit history. The execution environment did not provide interactive desktop/mobile browser instances, so the audit does not claim live validation on every Safari, Firefox, Chromium, iOS, or Android release. The report distinguishes confirmed code defects from portability risks requiring a browser test matrix.

  • Open index.php over HTTPS.
  • Verify loader dismisses after all section counts settle.
  • Export twice and compare stable hash on an unchanged browser.
  • Repeat in Chromium, Firefox, desktop Safari, and iOS Safari.
  • Inspect exported server data for secrets before broader deployment.
